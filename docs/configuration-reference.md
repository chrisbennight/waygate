# Runtime setting reference

Use [configuration](configuration.md) for setup instructions. This reference owns
setting names, defaults, formats, and credential groups. Leave unused optional
settings absent; source readers define the behavior of the deployed version.

| Var | What |
|-----|------|
| `GATEWAY_LISTEN_ADDR` | Listener address; default `0.0.0.0:8080`. Use loopback for a native local listener. Container interface binding and host publication are separate controls. |
| `GATEWAY_AUDIENCE` | Expected access-token audience; defaults to the public URL. |
| `GATEWAY_SKILLS_GIT_API_URL` / `GATEWAY_SKILLS_GIT_REPOSITORY` / `GATEWAY_SKILLS_GIT_ROOTS` | Required together for Git skills; see [source configuration](skills-git-source.md). |
| `GATEWAY_SKILLS_SOURCE_ID` | Explicit stable identity for the Git skills source and its `skill://` namespace. |
| `GATEWAY_SKILLS_GIT_TOKEN_ENV` | Name of the environment variable containing the repository credential, not the credential itself. |
| `GATEWAY_DEPLOYMENT_PROFILE` | `dev` (default) or `prod`. `prod` refuses to boot with known-unsafe defaults (auth disabled, `accept_upstream_tokens=true`, no audit DB, no dashboard auth, stdio upstreams). Set explicitly on every prod deploy. |
| `GATEWAY_PUBLIC_URL` | Public HTTPS origin used by clients, the gateway issuer, and default callback URLs. Derived from the listener unless set explicitly. |
| `GATEWAY_MCP_ALLOWED_ORIGINS` | Comma-separated HTTP(S) origins permitted on MCP requests. Unset allows the origin of `GATEWAY_PUBLIC_URL`; an explicit list replaces it, and empty permits only requests without `Origin`. Matching uses scheme, host, and effective port. Invalid or unlisted headers return 403 before authentication; Host and bearer checks still apply. See [MCP browser origins](agents/identity.md#mcp-browser-origins). |
| `GATEWAY_AUTH_MODE` | `enforce` (default) or `disabled` (dev only — release builds reject `disabled` and `prod` profile refuses it on top of that) |
| `AUTHENTIK_ISSUER` | OIDC issuer URL — required when `auth_mode=enforce` |
| `GATEWAY_DATABASE_URL` | PostgreSQL connection URL. Required by the production profile, built-in authorization server, and durable file/Code Mode features. Unset uses a warning-producing null audit sink in development. Contains a database credential. |
| `GATEWAY_FILE_STORAGE_DIR` | Enables out-of-context uploads and downloads. Files stream through this directory for later upstream delivery or client download. Requires `GATEWAY_DATABASE_URL`; use storage shared by every serving replica. Unset disables both production transfer paths. |
| `GATEWAY_FILE_RETENTION_SECONDS` | How long a stored inbound or outbound file remains available. Default `86400` (24 hours); range `60..=2592000`. Expiry stops new delivery or download attempts but does not cut off a stream already in progress. |
| `GATEWAY_FILE_SECRET_RETENTION_SECONDS` | Retention for files an upstream marks `"sensitivity": "secret"` in its `files/authorizeDownload` result. Default `300` (5 minutes); range `30..=3600`, clamped to `GATEWAY_FILE_RETENTION_SECONDS` when that is shorter — the hint can only shorten a file's life. Files without the hint use the general retention. |
| `GATEWAY_FILE_MAX_BYTES` | Ceiling on the staged bytes of one tool call, counted across every file the result carries. Default `1073741824` (1 GiB); range `1..=i64::MAX`. Raise it if the deployment moves larger files — there is no "unlimited" setting, because an absent cap let a single upstream stream until the storage volume filled. The gateway always streams and still enforces any smaller size declared by the sending file value. |
| `GATEWAY_FILE_TRANSFER_CONCURRENCY` | Maximum simultaneous inbound and outbound file streams per gateway process. Default `8`; range `1..=1024`. Each owner (tenant, issuer, subject) may use at most half, rounded up. Admission is immediate and separate from normal MCP call concurrency. Client uploads must deliver 64 KiB or finish within each 30-second progress window; see [file transfer](file-transfer.md). |
| `GATEWAY_DATABASE_AUDIT_MAX_CONNECTIONS` / `GATEWAY_DATABASE_CONTROL_MAX_CONNECTIONS` / `GATEWAY_DATABASE_READER_MAX_CONNECTIONS` | Reserved Postgres capacity for audit persistence, control-plane stores, and dashboard reads. Defaults to `8` each (24 total). Audit and reader pools must each be at least 1; the control pool must be at least 3 because the fleet doorbell listener and a fleet retention claim can each hold one connection while the retention stores and other control work need another. The sum may not exceed 64. Audit and control pools are required at boot. If the reader pool cannot connect, reads fall back to the control pool while audit capacity remains isolated. `/metrics` exposes live `mcp_database_pool_connections{role,state}` pressure. |
| `GATEWAY_IDENTITY_SIGNING_KEY_PATH` / `GATEWAY_IDENTITY_SIGNING_KEY_PEM` / `GATEWAY_IDENTITY_KID` | Select exactly one signing-key source: a path or inline Ed25519 PKCS8 PEM. Prefer a read-only secret mount. KID labels the public key and defaults to `gateway-v1`. The multi-key settings below take precedence. |
| `GATEWAY_IDENTITY_JWT_KEYS` / `GATEWAY_IDENTITY_JWT_ACTIVE` | Multi-key rotation. `KEYS=<kid1>:<path1>,<kid2>:<path2>,…` declares the keyring (PEM file per kid); `ACTIVE=<kid>` selects which one signs. Every kid in `KEYS` is published in `/.well-known/jwks.json`, so verifiers can validate tokens signed under any kid still in the set — drop a kid only after every token signed by it has expired. Both vars must be set together; setting them disables the single-key shape above. |
| `GATEWAY_INTROSPECTION_URL` / `_CLIENT_ID` / `_CLIENT_SECRET` | enable the RFC 7662 OAuth token-introspection validator for OPAQUE bearer tokens (Authentik `provider_type=oauth2` with no signing key, etc.). All three required together; setting only some is a fatal config error. **When the built-in AS is enabled (`GATEWAY_AS_ENABLED=true`), the validator is only wired if `GATEWAY_ACCEPT_UPSTREAM_TOKENS=true` is ALSO set** — same opt-in gate as the upstream-JWT validator, so the AS-mode anti-pattern of accepting upstream tokens directly stays off by default. Boot log WARNs when the introspection triple is configured but the gate is closed. The validator slots between the JWT validator and the API-key validator in the bearer chain — JWT-shaped tokens (3 base64url segments) skip via structural filter, API-key-shaped (`mcpgw_…`) skip too. Each cold-cache token costs one HTTP POST to the IdP; active responses cached for `min(exp - now, GATEWAY_INTROSPECTION_CACHE_TTL_SECONDS)` (default ceiling 300s), inactive responses cached for `GATEWAY_INTROSPECTION_NEG_CACHE_TTL_SECONDS` (default 30s). |
| `GATEWAY_DASHBOARD_CLIENT_ID` / `GATEWAY_DASHBOARD_CLIENT_SECRET` / `GATEWAY_DASHBOARD_SESSION_KEY` | Dashboard OAuth client identifier, secret, and distinct random 32-byte session key encoded as base64 or 64 hexadecimal characters. Callback defaults to `<public URL>/admin/auth/callback`. All absent disables dashboard login in development; a partial group fails startup. |
| `GATEWAY_TOKEN_EXCHANGE_*` | Enable Tier A (RFC 8693) identity chaining |
| `GATEWAY_AS_ENABLED` | `true` turns on the built-in OAuth AS (CIMD flow) |
| `GATEWAY_AS_UPSTREAM_CLIENT_ID` / `GATEWAY_AS_UPSTREAM_CLIENT_SECRET` | Separate OAuth client for the built-in authorization server. With `GATEWAY_AS_ENABLED=true`, supply this pair, the issuer, database, signing key, and upstream-token encryption key. Callback defaults to `<public URL>/oauth/callback`. |
| `GATEWAY_UPSTREAM_TOKEN_KEY_<id>` | Base64-encoded 32-byte AES-256-GCM encryption key for upstream tokens at rest; `GATEWAY_UPSTREAM_TOKEN_KEY_V1=<base64>`, `_V2=<base64>`, etc. Each row stamps the id that produced its ciphertext, so an operator can add a new key alongside the old, flip `_ACTIVE_ID`, and let the refresh path and the background re-encrypt sweeper (configured via `GATEWAY_UPSTREAM_REENCRYPT_INTERVAL_SECONDS` below) advance rows forward without an outage. |
| `GATEWAY_UPSTREAM_TOKEN_KEY_ACTIVE_ID` | Id of the keyring entry used for new encrypts. Required when more than one `_<id>` key is configured; defaults to the single configured id otherwise. Key IDs are normalized to lowercase; retain each key until no stored row requires it. |
| `GATEWAY_UPSTREAM_REENCRYPT_INTERVAL_SECONDS` | Cadence (default `3600`) for the background sweeper that re-encrypts `user_upstream_sessions` rows whose `key_id` lags the active id, advancing them under the current key. Floor `60`; `0` disables. Cheap at idle (SQL filter on `key_id <> active` returns zero rows in steady state) — leaving it on makes the next rotation a non-event. |
| `GATEWAY_AS_CIMD_ALLOWED_HOSTS` | Optional comma-list restricting which hosts may serve CIMD docs |
| `GATEWAY_ACCEPT_UPSTREAM_TOKENS` | Development-only opt-in to accept Authentik-issued tokens alongside gateway-issued tokens when the built-in authorization server is enabled. This supports external-issuer service-account flows. Defaults off, emits a startup warning when enabled, and is refused by the production profile. |
| `GATEWAY_SERVERS_DIR` | Where upstream manifests live (default `/etc/mcp-gateway/servers`) |
| `GATEWAY_POLICIES_DIR` | Where the default tenant's Cedar policies live (default `/etc/mcp-gateway/policies`); non-default tenants load their latest published bundle from the policy ledger. |
| `GATEWAY_POLICY_EDITING` | `true` (default) lets the dashboard / REST edit Cedar policies in place; `0`/`false`/`no`/`off` makes the policy surface read-only. Even when on, editing is auto-disabled (with a shown reason) if `GATEWAY_POLICIES_DIR` is not writable — a default-tenant publish mirrors the bundle onto `policies/*.cedar`, so the dir must be a **persistent writable volume** for an edit to survive a restart. The image does not bake a default policy set, so seed that volume through a governed publish or supported import before first boot (a fresh volume is empty; multi-replica needs a shared volume). Non-default tenants are ledger-backed. See `server-config-source-of-truth.md` → "Operational requirements". |
| `GATEWAY_REPLICA_ID` | This replica's id in per-replica activation audit events (fleet observability). Defaults to the container/pod `HOSTNAME`, then a process-scoped `replica-pid<N>` for local/dev — set explicitly only to override the auto-derived value. |
| `GATEWAY_EAGER_TOOLS_LIST` | `true` makes legacy-session `tools/list` return the full upstream catalog up-front. Defeats the closed-draft SEP #1888 compatibility behavior on that lane — only set for legacy clients that ignore `notifications/tools/list_changed` (e.g. Claude Code, [#13646](https://github.com/anthropics/claude-code/issues/13646)). MCP 2026 clients already receive a stable full authorized catalog, so this flag does not change their projection. |
| `GATEWAY_CODEMODE_RESULT_STORAGE` | Explicit Code Mode information-flow decision: `disabled` (default) stores lifecycle and non-content outcome metadata only; `allow` permits bounded retained source, caller-supplied program input, intermediate artifacts, checkpoints/resume input, and successful results to be retained in the control database for their documented windows. Program input is caller-controlled content bound alongside the source so a resumed attempt replays what it was submitted with, and it is retained for the same execution window — treat it as you would the source when deciding what may cross this boundary. MCP task augmentation and stable content references are advertised only with `allow` plus a configured database, so clients never receive a retrieval contract the gateway cannot honor. |
| `GATEWAY_CODEMODE_EXECUTION_LIMIT_SECONDS` | Default execution budget in seconds, `300` (5 minutes). Positive and no greater than `GATEWAY_CODEMODE_EXECUTION_MAX_SECONDS`. Callers may request a shorter `timeout_seconds`; setup has its own deadline. |
| `GATEWAY_CODEMODE_MAX_CONCURRENT_EXECUTIONS` | Maximum active runner attempts per process. Default is `GATEWAY_CODEMODE_EXECUTION_MEMORY_BYTES` divided by the estimated total peak memory per runner. Positive; explicit overrides require operator sizing. Replicas have independent pools. |
| `GATEWAY_CODEMODE_MAX_CONCURRENT_EXECUTIONS_PER_TENANT` | Per-tenant active runners. Default is one quarter of global concurrency rounded up, minimum one; cannot exceed global concurrency. |
| `GATEWAY_CODEMODE_MAX_CONCURRENT_DETACHED_EXECUTIONS` | Detached active runners. Default is half of global concurrency, minimum one; cannot exceed global concurrency. Detached attempts also consume global and tenant permits. |
| `GATEWAY_EAGER_TOOLS_CLIENTS` | Comma-separated exact MCP `clientInfo.name` values whose legacy sessions receive the full authorized catalog, matched at `initialize`. ASCII-case-insensitive; defaults to `claude-code,codex-mcp-client`. Those clients do not currently turn `notifications/tools/list_changed` into newly callable bindings. An explicit empty value disables this automatic compatibility fallback. `GATEWAY_EAGER_TOOLS_LIST=true` still forces eager mode for every legacy client. MCP 2026 clients always receive the stable full authorized projection. Client names are self-asserted, so this is a context-size compatibility control, not an authorization boundary. |
| `GATEWAY_ROOT_COMPOSITION_CLIENTS` | Comma-separated exact MCP `clientInfo.name` values selecting presentation-only root-composition schema adaptation. ASCII-case-insensitive; unset by default. Independent of eager/compact catalog settings. Full schemas remain enforced on calls and returned by inspection and Code Mode. See [client schema compatibility](client-schema-compatibility.md) for supported shapes, diagnostics, and rollback. |
| `GATEWAY_CODEMODE_ONLY_CLIENTS` | Comma-separated exact MCP `clientInfo.name` values that receive only authorized gateway built-ins, including the `codemode.*` discovery and execution facade. This compact projection applies to legacy and MCP 2026 requests because it targets hosts that both cap the initial tool count and do not apply dynamic list changes. ASCII-case-insensitive; unset by default. A name may not also appear in `GATEWAY_EAGER_TOOLS_CLIENTS`, and the setting is rejected while `GATEWAY_EAGER_TOOLS_LIST=true`. Client names are self-asserted and change only catalog size, never authorization. After changing this setting, reconnect a legacy client so it performs a new initialize handshake; a stateless MCP 2026 client applies the setting on its next request. Cursor reports both [no progressive tool loading](https://forum.cursor.com/t/cli-mcp-tool-limits/165642/8) and [ignored `notifications/tools/list_changed`](https://forum.cursor.com/t/mcp-notifications-tools-list-changed-not-acted-on-mid-session/161459), which is the compatibility case this mode covers. |
| `GATEWAY_SESSION_KEEPALIVE_SECONDS` | Idle timeout on each `Mcp-Session-Id`. Default `604800` (7 days). Floor 60s; `0` disables. rmcp's default is 5 min — too short for Claude Code, which doesn't re-handshake on a stale session ([claude-code#27142](https://github.com/anthropics/claude-code/issues/27142)). Not the SSE heartbeat — that's `GATEWAY_SSE_KEEPALIVE_SECONDS` below: this bounds how long idle *session state* lives; that keeps the *stream* warm. |
| `GATEWAY_SSE_KEEPALIVE_SECONDS` | Interval between SSE keepalive comment frames (`:` heartbeats) on every open streamable-HTTP SSE stream — the standalone GET stream and long-running POST response streams. These bytes stop intermediaries with idle-read timeouts (squid `read_timeout`, nginx `proxy_read_timeout`, ALB idle timeout) from reaping a healthy-but-quiet stream between tool calls. Default `120`. Floor 5s; `0` disables (idle streams then emit nothing and WILL be reaped by any idle-timeout hop). Deployments behind a 60s-idle intermediary (ALB default, stock nginx `proxy_read_timeout`) should set ≤ `55`. Overrides rmcp's baked-in 15s default in both directions so this knob is the single source of truth. |
| `GATEWAY_MCP_PING_INTERVAL_SECONDS` | Interval between server-initiated MCP `ping` requests per session — the spec's connection-health probe, layered above the SSE comment frames: each ping is a real JSON-RPC request the client answers, so bytes flow in both directions and the gateway learns whether the client is actually reachable (`mcp_client_pings_total`). Default `120`. Floor 10s; `0` disables. A session whose pings are answered never hits the `GATEWAY_SESSION_KEEPALIVE_SECONDS` idle reap (outbound pings re-arm the idle timer); after 3 consecutive unanswered pings the loop stops for that session so the idle timer regains control over dead clients. |
| `GATEWAY_DRAIN_TIMEOUT_SECONDS` | Total wall-clock budget for post-SIGTERM cleanup — axum HTTP drain PLUS DB pool close — before forced exit. Default `20` (leaves ~10s headroom under the typical 30s `terminationGracePeriodSeconds` so the process logs + exits before SIGKILL). Range `1..=600`. The timer starts from the shutdown signal, not from boot. On timeout the process exits and dropped HTTP/DB connections close on socket teardown. |
| `GATEWAY_UPSTREAM_CALL_TIMEOUT_SECONDS` | Hard timeout on each upstream `tools/call`, `resources/list`, and `resources/read` operation. Default `300` (5 minutes). Floor 5s; `0` disables. Applies globally to every forwarded operation — no per-tool or per-resource override. Without it, a wedged upstream stream (long-idle HTTP/2 that silently half-closed) holds the connection slot inside `waygate_upstream::pool` and blocks every other call routed to it until the gateway restarts. |
| `GATEWAY_RESOURCE_RESPONSE_MAX_BYTES` | Raw response-body ceiling for one native `resources/read`, enforced before rmcp deserializes an upstream response. Default `4194304` (4 MiB); range `1..=1073741824` (1 GiB). An over-limit streamable-HTTP response—whether JSON or SSE-framed—returns `data.error = "resource_response_too_large"` with `limit_bytes`; legacy SSE and stdio transports return `bounded_resource_read_unsupported` because they cannot enforce a pre-buffer bound. Governed file responses remain useful at the 4 MiB default because this limit covers only their small MCP descriptor; streamed file bytes use `GATEWAY_FILE_MAX_BYTES` independently. |
| `GATEWAY_UPSTREAM_POOL_SIZE` | Connection lanes dialed per network upstream (HTTP/SSE) so concurrent calls to one upstream run in parallel instead of serializing on a single connection. Default `4`; values `< 1` clamp to `1`. Stdio upstreams are always a single child process regardless. |
| `GATEWAY_QUARANTINE_ON_DRIFT_RISK` | When a tool's live behavior hash changes, auto-quarantine it if it meets this threshold. In `mcp_annotations` mode the hash covers name, description, input/output schemas, standard MCP annotations, and the complete namespaced metadata; `manifest` mode hashes the name, description, and input schema. The `high` / `medium` thresholds cover the named catalog risk tier **or** any side-effecting tool (annotation-native tools count as side-effecting while their claims remain conservatively classified); `all` covers everything and `off` (default) nothing. Quarantined tools are hidden and refused. With a database, tool-change quarantine and before/after evidence survive restart; use [tool change review](guides/security.md#review-an-upstream-tool-change) to accept an exact replacement. Without a database, quarantine remains process-local. See [the annotation authority contract](agents/upstreams.md#classification-authority-claims-are-not-policy). |
| `GATEWAY_CATALOG_STRICT_PENDING_APPROVAL` | When `true`, a catalog `PendingApproval` result refuses dispatch (returns `ResolvedInvocationTool::Quarantined`) instead of falling back to manifest classification. Default `false` (transitional behavior — un-approved catalog tools still dispatch against manifest facts). Production reconciles the accepted manifest set before serving and treats the governed catalog as authoritative, so a catalog `NotFound` result or database error refuses dispatch rather than reviving a withdrawn tool. Manifest fallback on those failure modes remains available only to non-authoritative embedders built with `with_catalog`. |
| `GATEWAY_REQUIRE_TWO_APPROVALS` | When `true`, `POST /api/v1/catalog/servers/{id}/approve` rejects with `409 Conflict` if the calling admin is the most-recent prior approver of the same server (two-person rule for promotion to `live`). Quarantine is deliberately exempt — operators must always be able to pull a misbehaving server out fast. Default `false`. |
| `GATEWAY_OVERVIEW_CHANGE_FEED_ACTIONS` | Comma-separated allowlist of change-request audit actions surfaced on the Overview "What changed" feed from the broad `admin_mutation` category, so the propose → approve → execute ceremony shows without every admin mutation (secret-retrievals, oauth/session revokes, …). Default `ChangeRequestPropose,ChangeRequestApprove,ChangeRequestExecute,ChangeRequestDeny`; empty/unset keeps the default (a blank value can't blank the feed). Shown read-only on the Settings page. |
| `GATEWAY_GRANT_SWEEP_INTERVAL_SECONDS` | Cadence of the background sweep that prunes consumed/expired HITL approval grants. Default `3600` (1h). `0` disables; floor `60`. Only runs when a Postgres catalog is wired. |
| `GATEWAY_GRANT_RETENTION_DAYS` | Minimum age (days) a dead grant row must reach before the sweep deletes it — keeps recent dead rows visible to the admin "history" view (`?include_consumed=true`). Default `7`. |
| `GATEWAY_HITL_WS_BUFFER` | Bounded broadcast-channel capacity for the HITL approval push hub backing `GET /api/v1/admin/approval_grants/subscribe`. Each in-flight `approval_needed` event takes one slot per subscriber until consumed; a subscriber that falls more than this many events behind receives a `RecvError::Lagged` warning and skips the gap. Default `256` — comfortable for a small operator team. Range `1..=65_536` (above that pick a real queue). The channel is process-wide today; multi-tenant bursts can therefore cause cross-tenant lag. |
| `GATEWAY_PII_REDACT` | Response-inspector opt-in. When set to `on`, the response-inspector chain runs the built-in `PiiInspector` against every successful upstream `CallToolResult` and every textual native resource content (blobs remain opaque); a match against the default ruleset (US SSN with SSA-invalid-prefix filter, US phone with URL false-positive filter, email, Luhn-valid credit card) returns `response_inspection_blocked` to the caller and refuses to forward the payload. Unset / any other value ⇒ inspection stays a no-op (default; existing deployments see zero behavior change). See `GATEWAY_PII_MODE` for the redact-instead-of-block toggle. |
| `GATEWAY_PII_MODE` | decision toggle for `GATEWAY_PII_REDACT=on`. `block` (default — every match refuses the call) or `redact` (every match replaced with `[REDACTED:<RULE>]` and the response is forwarded). Redaction makes the orchestrator emit ONE summary `CallTool/Success` audit row per inspection (`reason="response inspector \`pii\` redacted N finding(s)"`) and bump `mcp_response_inspector_redactions_total{server,tool,inspector}` instead of `_blocks_total`. Subsequent inspectors in the chain see the redacted output (redactions compose). |
| `GATEWAY_SECRET_REDACT` | response-inspector opt-in, parallel to `GATEWAY_PII_REDACT`. When set to `on`, the inspector chain also runs the built-in `SecretsInspector` — detects AWS access keys (`AKIA…` / `ASIA…`), GitHub tokens (`ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` prefixes), JWTs (three base64url segments with `eyJ` header), and PEM private-key armor headers (RSA / EC / DSA / OpenSSH / encrypted / unqualified). Pattern matches can have false positives; reason field carries only the rule label, never the matched token. Unset / any other value ⇒ secret inspection stays off (default). Additional credential formats and per-tenant overrides require separate support. Pattern detection does not establish exhaustive secret coverage. |
| `GATEWAY_POISONING_REDACT` | response-inspector opt-in, parallel to the PII / secret env vars. When set to `on`, the inspector chain also runs the built-in `PoisoningInspector` — detects raw LLM chat-template control tokens (`<\|im_start\|>`, `[INST]`, `<\|system\|>`, etc.), the canonical "ignore previous instructions" canary (case-insensitive, plus `disregard…` / `forget…` variants), role-impersonation lines (`\nsystem:` / `\nassistant:` / `\nuser:` at line-start), and embedded `system prompt:` markers. Pattern-based only — adversarial detection done well needs an ML model; classifier-based detection is not provided by this inspector. Unset / any other value ⇒ poisoning inspection stays off (default). External adapters (Lakera / ZenGuard / Prompt Armor) and obfuscated-variant detection (base64-wrapped instructions, Unicode lookalikes, zero-width splits) are not implemented by this inspector. |
| `GATEWAY_EVIDENCE_OUTBOX_TARGETS` | Comma-separated allowlist of target-sink identifiers (`webhook`, `ocsf`, `ecs`, `syslog`; for example, `webhook,ocsf`) the recorder may write outbox rows for. Unknown identifiers are rejected at startup. Configure the corresponding destination below: `GATEWAY_EVIDENCE_WEBHOOK_URL`, `GATEWAY_EVIDENCE_OCSF_URL`, `GATEWAY_EVIDENCE_ECS_URL`, or `GATEWAY_EVIDENCE_SYSLOG_TARGET`. Unset/empty disables outbox enqueueing. With no per-tenant routing rows, the full configured list applies; when routing rows exist, their enabled targets narrow the configured list by intersection. Required audit rows and hierarchy-bearing chained-best-effort rows enqueue configured targets atomically with the audit INSERT; the latter retain non-blocking lock acquisition and the one-second best-effort transaction deadline. Direct chained-best-effort and unchained best-effort rows skip the outbox. The drain worker consumes the resulting rows, and this setting only takes effect when `GATEWAY_DATABASE_URL` is set. |
| `GATEWAY_EVIDENCE_DRAIN_INTERVAL_SECONDS` | Cadence of the evidence outbox drain worker that ships pending outbox rows via the registered exporters. Default `30`. `0` disables; floor `5`. Only runs when a DB pool exists AND at least one exporter could be registered. |
| `GATEWAY_RETENTION_SWEEP_INTERVAL_SECONDS` | Cadence of the periodic retention sweep scheduler that consumes `evidence_retention_policy` rows and runs bounded per-tenant transactions through `audit_log_sweep_delete()`. Default `3600` (hourly); `0` disables; floor `60`. A running scheduler deletes nothing until a policy exists. Explicit category policies take precedence; a wildcard (`*`) policy sweeps the tenant's remaining categories. A fleet lock prevents overlapping passes even when work outlives the cadence, a durable database claim deduplicates phase-skewed replicas, each policy gets at most 10 batches of 500 rows in that pass, and structured logs report deletions, errors, and remaining backlog. Each chained-row marker records a compact bridge locator; chain verification follows only paths reachable from gaps in its bounded row window and logs both the gap and reachable-marker counts. Only runs when a Postgres pool exists. |
| `GATEWAY_AUDIT_ROLLUP_INTERVAL_SECONDS` | Cadence of the Tier-2 audit rollup worker that keeps `audit_rollup_hourly` current for fast wide-window dashboard reads. Default `60` (~1-min currency); **default-ON**. Steady-state ticks are a cheap idempotent recompute of only the recent (in-window) hours, BUT the **first tick after a deploy (or any rollup reset) does a one-time full backfill** — it scans the whole `audit_log` to populate every historical hour, which on a large table is a multi-second aggregate. `0` disables; floor `10`. Only runs when a Postgres pool exists. The rollup is an independent long-term aggregate: with retention enabled it intentionally outlives swept raw rows. |
| `GATEWAY_EVIDENCE_WEBHOOK_URL` | HTTP-POST destination for the `webhook` exporter. When set AND `webhook` is in `GATEWAY_EVIDENCE_OUTBOX_TARGETS`, the drain ships each audit event's JSON to this URL. Includes `X-Evidence-Event-Id` header for idempotency-keying on the remote. 4xx → permanent (dead-letter); 5xx + network errors → retry with exponential backoff capped at 1h; row dead-letters after 8 transient failures. |
| `GATEWAY_EVIDENCE_OCSF_URL` | HTTP-POST destination for the `ocsf` exporter. When set AND `ocsf` is in `GATEWAY_EVIDENCE_OUTBOX_TARGETS`, the drain ships each audit event as an OCSF 1.7 Application Activity record (`class_uid = 6003`). Standard fields (`metadata`, `actor.user`, `time` as ms-since-epoch, `status_id`, `severity_id`, `status_detail`) populated from the audit event; tool identity rides in the OCSF standard `app_uid` slot (`"<server>.<tool>"`); the remaining gateway specifics (audit category, the selected operation for a tool that carries many, risk tier, PII flag, policy ids) ride in `enrichments`, including an `invocation_hierarchy` enrichment for nested calls. Same retry shape as the webhook exporter. Typical destinations: fluentd HTTP source, Datadog logs ingest, Splunk HEC. |
| `GATEWAY_OCSF_AOS_TRACE` | opt-in: when `true` (default `false`), each OCSF record gains an additional `enrichments` block (`name: "aos_trace"`, `type: "owasp"`) carrying the OWASP Agentic Apps Security trace context — actor chain (`user:<sub>`, `gateway:mcp-gateway`), fully-qualified tool, risk tier, PII flag, decision, policy ids, reason, latency, trace id. Append-only — existing enrichments stay byte-stable. AOS-aware SIEM rules pluck the block out by `enrichments[?(@.name=='aos_trace')]`. Leave unset for SIEM destinations that haven't yet been updated to handle the additional block. |
| `GATEWAY_EVIDENCE_ECS_URL` | HTTP-POST destination for the `ecs` exporter. When set AND `ecs` is in `GATEWAY_EVIDENCE_OUTBOX_TARGETS`, the drain ships **one ECS 8.x document per HTTP POST** (`Content-Type: application/json`) to this URL. Standard ECS fields (`@timestamp` RFC3339, `event.action`/`event.category`/`event.kind`/`event.outcome`/`event.severity`/`event.duration` in ns, `user.id`/`user.email`/`user.roles`/`user.domain`, `related.user` for cross-doc pivot, `service.name`) populated from the audit event; AI-agent specifics (tool, the selected `operation` for a tool that carries many, risk tier, PII flag, policy ids, tenant id, gateway category) ride in `labels`. Nested calls add `parent_execution_id`, `execution_step`, `execution_call_id`, and `execution_attempt` labels. `event.kind="alert"` on high-risk denials and security-category events for Kibana SIEM rules; otherwise `"event"`. Same retry shape as the other HTTP exporters. The destination should be a fluentd / logstash / Elasticsearch-ingest-pipeline receiver that aggregates per-event posts into bulk indexing; direct Elasticsearch `_bulk` endpoints are not supported (they require NDJSON framing with action lines). |
| `GATEWAY_EVIDENCE_SYSLOG_TARGET` | TCP target (`host:port`) for the `syslog` exporter. When set AND `syslog` is in `GATEWAY_EVIDENCE_OUTBOX_TARGETS`, the drain ships each audit event as an RFC 5424 line over plain TCP (RFC 6587 non-transparent framing — newline-terminated). Priority = `facility * 8 + severity` where severity is derived from `(outcome, risk_tier)` (high-risk denials → err 3, high-risk success → warning 4, etc.); gateway-specific fields ride in RFC 5424 structured-data blocks (`mcp@<pen>`, `principal@<pen>`, `tool@<pen>` — which carries an `operation` parameter when the call selected one — `policy@<pen>`, and `execution@<pen>` for nested calls). Per-event TCP connect + write + close, 5s timeout per send. **Plain TCP only** — operators wanting TLS front the receiver with stunnel / haproxy / a TLS sidecar. Typical destinations: rsyslog / syslog-ng on-prem, network-appliance receivers, SIEM forwarders. |
| `GATEWAY_EVIDENCE_SYSLOG_HOSTNAME` | RFC 5424 HOSTNAME field value the syslog exporter places in each line. Default `mcp-gateway`. Override per-host when running multiple gateway instances so SIEM rules can route by instance. |
| `GATEWAY_EVIDENCE_SYSLOG_FACILITY` | Syslog facility code 0–23 per RFC 5424 §6.2.1. Default `16` (local0). |
| `GATEWAY_EVIDENCE_SYSLOG_PEN` | IANA Private Enterprise Number for the RFC 5424 structured-data blocks. Default `32473` (RFC 5612 example PEN); operators with an assigned PEN should override. |
| `GATEWAY_EVIDENCE_BUNDLE_SIGNING_KEY_PEM` | PKCS8-PEM-encoded Ed25519 private key the `POST /api/v1/audit/bundle` endpoint signs evidence bundles with. Bundles are NDJSON: one header line, one row per `audit_log` event in the requested `(tenant, window, principal?, tool?)` slice, one footer line carrying the Ed25519 signature over `sha256(header_line + "\n" + each row line)`. Compliance auditors verify offline against the operator's published public key — no live gateway access needed. `None` ⇒ the bundle endpoint 503s with a "signing key not configured" message. |
| `GATEWAY_EVIDENCE_BUNDLE_SIGNING_KEY_ID` | Optional human-readable label for the bundle signing key (e.g. `"bundle-2026-q2"`) embedded in every bundle header so recipients match against the operator's published key list. `None` ⇒ derive the id from the first 16 hex chars of `sha256(verifying_key)`. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | OTLP collector endpoint (e.g. `http://otel-collector:4317`). Traces export over gRPC only; `OTEL_EXPORTER_OTLP_PROTOCOL` is not supported. Unset disables OTLP export; structured logs remain available on stdout. |
| `OTEL_SERVICE_NAME` | Overrides the application's default telemetry service name. |
| `LLM_CRED_<PROVIDER>_<LABEL>` | Injected LLM provider credential. `<PROVIDER>` ∈ `OPENAI` / `ANTHROPIC` / `GOOGLE` / `OPENROUTER` (`GEMINI` aliases `GOOGLE`); `<LABEL>` is an operator-meaningful account name, and the set of labels for a provider is its pool. OAuth providers (OpenAI, Google) take a JSON token blob; API-key providers (Anthropic, OpenRouter) the bare key. Injected by Infisical at deploy — never committed. See `inference-plane.md` §6. |
| `LLM_OAUTH_<PROVIDER>_CLIENT_ID` / `_CLIENT_SECRET` / `_TOKEN_URL` | Optional overrides for a provider's in-process OAuth refresh client. OpenAI and Google ship built-in public-CLI defaults; Google's installed-app refresh additionally requires `LLM_OAUTH_GOOGLE_CLIENT_SECRET` to be injected (the public Gemini-CLI secret — kept out of source per invariant I4). Overrides apply only to a provider that already has a built-in default. |
| `GATEWAY_LLM_DISCOVERY` | Opt-in dynamic model discovery: a JSON array of `{"provider","credential_label","base_url"}` targets whose live model lists the gateway fetches and registers in the catalog (so models need not be hand-listed in `GATEWAY_LLM_MODELS`). **At most one target per provider** — reconciliation is provider-scoped, so a duplicate provider is dropped (first wins) with a warning. **`openrouter` (api-key, with pricing) and OpenAI Codex (subscription OAuth, no pricing) are wired today**; other providers — including Anthropic (first-party `x-api-key`) and Gemini — are dropped with a warning and stay operator-pinned. A Codex target additionally accepts an optional `"client_version"` pin (all-digit `MAJOR.MINOR.PATCH`) for the version the ChatGPT backend scopes its model listing to; a malformed pin is dropped with a warning (the target survives). **Without a pin, the refresher tracks the latest released Codex CLI version itself** — unauthenticated GETs to the npm registry (`@openai/codex/latest`) with the GitHub latest-release as fallback, cached 24h, falling back through the last successful fetch to a compiled default — so expect that release-metadata egress from the discovery refresher when an unpinned Codex target is configured. Enabling it (even with no `GATEWAY_LLM_MODELS` pins) activates the inference plane and the `/v1` routes. Unset/empty ⇒ discovery is off. Discovered rows are provider-namespaced (`openrouter:<id>`, `openai:<id>`), soft-disabled (never deleted) when a model disappears, and never clobber an operator pin or operator-set pricing. The upstream name `llm` is reserved for inference and is refused in upstream manifests, even when inference is disabled. |
| `GATEWAY_LLM_DISCOVERY_INTERVAL_SECS` | Discovery refresh interval. Default `10800` (3h); values below `300` (the 5-min floor, so a misconfiguration can't hammer providers) or unparseable values reject at boot. The refresher also runs once on boot. Only meaningful when `GATEWAY_LLM_DISCOVERY` is set. |
| `GATEWAY_LLM_CACHE_ENABLED` | master switch for the per-principal exact-match response cache — chat completions **and** embeddings (`inference-plane.md` §9). `1`/`true`/`yes` enables it; **unset / anything else ⇒ off (default)**. This is the one place the gateway stores response *content*, so it is opt-in at the system level. Caching also requires a per-model `cache_ttl_ms` in `GATEWAY_LLM_MODELS` — both the flag and a model TTL must be set for a model to cache. Entries are per-principal keyed (a hit never crosses users); for chat the key is transport-agnostic (a unary-stored body serves a streaming hit and vice versa), and embeddings (unary-only) replay their stored body verbatim. |
| `GATEWAY_LLM_CACHE_SWEEP_SECONDS` | Interval of the completion cache's TTL sweep, which reclaims expired rows' disk (reads already filter on expiry, so the sweep never affects correctness — only storage). Default `300`; `0` disables the sweeper. Only runs when caching is active (`GATEWAY_LLM_CACHE_ENABLED` + a DB pool). |
| `GATEWAY_LLM_CACHE_MAX_ROWS_PER_TENANT` | Hard per-tenant cap on cache entries, enforced (evict-oldest by `created_at`) after each store — bounds growth *within* a TTL window, complementing the TTL sweep. Default `10000`; `0` ⇒ unbounded by count (TTL + sweep only). |
| `GATEWAY_LLM_EGRESS_PROXY` | Optional **`http://` / `https://`** proxy URL for **LLM provider calls only** — scoped to the inference HTTP client, so it does NOT reroute the gateway's other HTTPS (OIDC, JWKS, discovery). The intended use is a **uTLS-terminating egress sidecar** that re-originates the upstream TLS with a CLI-like ClientHello: the JA3/JA4 *transport* fingerprint is the one vector header fidelity cannot address (reqwest's TLS stack differs from the real CLIs'), and this gateway does not swap its in-process TLS stack. Most relevant for the OAuth-gated **Codex** backend (and any upstream behind a TLS-fingerprinting CDN). SOCKS is **not** supported (the workspace builds `reqwest` without its `socks` feature). Unset ⇒ reqwest's default (which still honors the system `*_PROXY` env vars). A malformed URL fails boot. The URL may embed proxy credentials and is **never logged**. See `inference-plane.md` → §13.1. |
| `GATEWAY_LLM_CRED_RELOAD` | Opt-in in-process re-read of externally-refreshed LLM credentials (tokens an external refresher publishes to Infisical). JSON array of `{"provider","label","secret"}` mapping a credential pool entry to the Infisical secret name to re-read it from. `provider` is resolved through the **same case-insensitive vocabulary as the `LLM_CRED_<PROVIDER>_<LABEL>` keys** above — including the `GEMINI`→`GOOGLE` alias — so those keys' provider strings (e.g. `ANTHROPIC`, `GEMINI`) work here verbatim. Empty/unset ⇒ the re-read poller does not run (credentials are then only as fresh as boot injection). An entry whose provider is unrecognized is dropped with a logged warning (never silently). Requires `GATEWAY_INFISICAL_*` below. |
| `GATEWAY_LLM_CRED_RELOAD_SECS` | Re-read interval for `GATEWAY_LLM_CRED_RELOAD`. Default `300`; `0` disables the poller. The gateway never refreshes these tokens itself (an out-of-band refresher owns their single-use rotation) — it serves the current token and re-reads the fresh one on this cadence. |
| `GATEWAY_INFISICAL_API_URL` / `GATEWAY_INFISICAL_TOKEN` / `GATEWAY_INFISICAL_PROJECT_ID` / `GATEWAY_INFISICAL_ENV` / `GATEWAY_INFISICAL_SECRET_PATH` | Coordinates for the credential re-read poller's read-only Infisical client. `TOKEN` should be a **scoped, read-only** service token (not the host machine identity) — its blast radius is exactly the secret path it reads. URL / TOKEN / PROJECT_ID enable the client; then ENV and SECRET_PATH are required explicitly. See [integration configuration](integration-configuration.md) for upgrade guidance and refresh ownership. |

## Code Mode resource budgets

Call `codemode.limits` to read effective limits before submitting a program.
Settings are resolved and validated at startup and passed explicitly to each
confined runner. Restart the gateway after changing them. All byte values are
integer bytes, with MiB meaning 1,048,576 bytes. Source limits count UTF-8 bytes;
JSON Schema's `maxLength` counts characters, so admission also checks byte size.

| Environment variable | Default or derivation |
| --- | --- |
| `GATEWAY_CODEMODE_SOURCE_MAX_BYTES` | 4 MiB for inline, uploaded, retained, and skill JavaScript |
| `GATEWAY_CODEMODE_HEAP_BYTES` | Maximum of 128 MiB and 32 times the source limit |
| `GATEWAY_CODEMODE_STACK_BYTES` | Heap divided by 64, bounded between 512 KiB and 8 MiB |
| `GATEWAY_CODEMODE_REQUEST_MAX_BYTES` | Heap divided by 16; includes mutation arguments |
| `GATEWAY_CODEMODE_CONNECTOR_RESPONSE_MAX_BYTES` | Heap divided by 4 |
| `GATEWAY_CODEMODE_RESULT_MAX_BYTES` | Heap divided by 16 |
| `GATEWAY_CODEMODE_INPUT_MAX_BYTES` | Heap divided by 16; program and resume input |
| `GATEWAY_CODEMODE_CHECKPOINT_MAX_BYTES` | Heap divided by 16 |
| `GATEWAY_CODEMODE_ARTIFACT_MAX_BYTES` | Heap divided by 16 |
| `GATEWAY_CODEMODE_MAX_ARTIFACTS` | 256 per attempt |
| `GATEWAY_CODEMODE_ARTIFACT_TOTAL_MAX_BYTES` | 16 times the individual artifact limit, per attempt |
| `GATEWAY_CODEMODE_QUERY_MAX_BYTES` | 4 KiB |
| `GATEWAY_CODEMODE_EXECUTION_MAX_SECONDS` | 86,400 seconds (24 hours); operator may lower it |
| `GATEWAY_CODEMODE_SETUP_TIMEOUT_SECONDS` | 30 seconds, separate from execution time |
| `GATEWAY_CODEMODE_RETAINED_SOURCE_BYTES_PER_OWNER` | 16 times the source limit |
| `GATEWAY_CODEMODE_RETAINED_SOURCE_BYTES_PER_TENANT` | 16 times the owner byte quota |
| `GATEWAY_CODEMODE_RETAINED_SOURCES_PER_OWNER` | 64 |
| `GATEWAY_CODEMODE_RETAINED_SOURCES_PER_TENANT` | 1,024 |
| `GATEWAY_CODEMODE_EXECUTION_MEMORY_BYTES` | 4 GiB allocated for deriving runner concurrency; reserve additional memory for the gateway and other workloads |
| `GATEWAY_CODEMODE_ADDRESS_SPACE_BYTES` | Maximum of 1 GiB and twice estimated peak runner memory |
| `GATEWAY_FILE_BUNDLE_MAX_FILES` | 64 distinct files in an elicitation response or file-backed resource response |
| `GATEWAY_FILE_BUNDLE_MAX_LOCATIONS` | Eight times the file count |
| `GATEWAY_RESOURCE_FILE_PREPARATION_SECONDS` | 30 seconds across the whole resource bundle |

Control frames derive from the largest admitted output or request plus an
allowance for metadata. Start frames account for worst-case source JSON escaping,
program input, checkpoint, resume input, and metadata, regardless of which input
fields happen to be present. The MCP HTTP body allowance uses the same derived
start-frame budget so source and input fit before Code Mode admission. Clients
do not configure frame limits separately.

Estimated peak runner memory includes twice the JavaScript heap, twice the start
frame allowance, four times the materialized connector response limit, and 64 MiB
for native runtime overhead. It is a conservative admission estimate, not an RSS
guarantee. Explicit concurrency overrides do not allocate memory; deployment
operators remain responsible for sizing and representative load testing.

Payloads and stack must fit the heap, address space and execution memory must
admit the estimated runner peak, and tenant retention quotas must contain owner
quotas. Arithmetic overflow and invalid settings fail startup. Retention quotas
remain enforced within the storage transaction. Existing transfer byte budgets,
execution deadlines, quotas, and approval rules continue to apply. Code Mode's
direct connector path has no separate call-count cap.
