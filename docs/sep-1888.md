# Legacy `searchTools` compatibility adapter

## Status and boundary

The gateway implements a frozen compatibility adapter inspired by the closed
[SEP #1888 proposal](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/1888).
It is not part of core MCP and is not an upstream-server contract. Ordinary
upstreams publish ordinary MCP `Tool` descriptors; the gateway alone projects
the synthetic `<server>.searchTools` tools for compatible downstream clients.

The current internal wire contract is
`gateway.search-tools.compat` version `1`, implemented in
[`compat/search_tools_v1.rs`](../crates/waygate-mcp/src/compat/search_tools_v1.rs).
A future incompatible adapter shape belongs in a new versioned module. The
[`search_tools`](../crates/waygate-mcp/src/search_tools.rs) module is only a
backward-compatible Rust re-export.

## Standard MCP path

MCP 2026 clients receive a stable, authorization- and admission-filtered
`tools/list` traversal containing direct `<server>.<tool>` declarations. The
gateway preserves each upstream tool's publishable title, description, input
schema, output schema, and annotations. Calling the compatibility search tool
does not change that list or its subscription stream.

The 2026 projection follows the MCP
[opaque-cursor pagination contract](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/pagination).
Page size is gateway-selected, an explicitly empty cursor starts the traversal,
and only an omitted `nextCursor` ends it. Every request rebuilds the authorized
canonical view. The server-minted continuation is authenticated and encrypted,
binds the complete non-credential principal projection and exact wire catalog,
and never grants access by possession. Expiry, mutation, cross-operation input,
or catalog or authorization-context drift returns `-32602` with restart guidance
instead of mixing pages from different views. Deployments share the existing
continuation key across replicas; without it, a process-local key keeps local
development safe but a restart or replica change requires traversal to restart.
Each page retains `ttlMs: 0` and `cacheScope: "private"`.

Legacy sessions remain unpaginated because their disclosure set is already a
compatibility projection and deployed legacy hosts cannot be assumed to follow
continuations. They accept an empty first-page cursor but never issue a
non-empty one.

An upstream may publish an ordinary tool named `searchTools`. On the MCP 2026
path, a visible and admitted direct tool takes precedence, is declared exactly
once, and dispatches through the normal governed invocation pipeline. A denied,
malformed, or quarantined collision cannot shadow the adapter or disclose its
existence.

Legacy sessions cannot disambiguate those two meanings at the same qualified
name. A call with a visible upstream collision therefore fails with the stable
`legacy_search_tools_name_collision` error and recovery guidance instead of
silently shadowing either contract.

## Frozen adapter v1 contract

The synthetic tool advertises:

- a human-readable title and action-oriented description that identify it as a
  gateway-owned, non-core compatibility surface;
- a schemars-derived input schema generated from the request DTO used at
  dispatch;
- a schemars-derived, legacy-object-rooted output schema generated from the
  response enum returned as `structuredContent`; and
- `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, and
  `openWorldHint: false` annotations.

`mode=operations` searches caller-visible, admitted tools and returns operation
descriptors. `mode=types` resolves a returned `#input` or `#output` handle to the
upstream's published JSON Schema after the same validation-equivalent
portability projection used by `tools/list`. The adapter never guesses a more
specific contract or fabricates a schema the upstream omitted. A schema that
depends on an unresolved remote reference cannot be made self-contained: an
input containing one is withheld, while an optional output schema containing
one is omitted.

Several v1 fields are gateway extensions rather than core MCP metadata or the
proposal's canonical vocabulary:

- `filters.query` uses the gateway's bounded BM25 index with a catalog fallback;
- `filters.riskLevel`, operation `riskLevel`, `scope`, and `sideEffects` expose
  gateway policy/classification facts;
- `filters.resourceType` is retained for compatibility but is an explicit no-op;
- `detail` controls the gateway's descriptor projection; and
- `cursor` is the adapter's opaque pagination offset.

No upstream is required to implement or understand any of these fields.

## Legacy disclosure lifecycle

A cold legacy `tools/list` contains the synthetic adapter for each visible
upstream. Operations returned by search are remembered for that session and
appear in subsequent `tools/list` results; newly disclosed names arm
`notifications/tools/list_changed`. Authorization and runtime admission are
re-evaluated on every list and call.

The optional `GATEWAY_EAGER_TOOLS_CLIENTS` and `GATEWAY_EAGER_TOOLS_LIST`
controls replace progressive disclosure with a full authorized legacy catalog
for clients that do not turn list-change notifications into newly callable
bindings. The per-client setting defaults to the exact wire names
`claude-code` and `codex-mcp-client`. These controls change context size, not
access control.

Some hosts have both a hard initial tool limit and no usable dynamic refresh.
For those hosts, `GATEWAY_CODEMODE_ONLY_CLIENTS` replaces the upstream
declarations and per-upstream `searchTools` adapters with authorized gateway
built-ins. Code Mode remains the governed discovery and invocation path through
`codemode.search`, `codemode.describe`, `codemode.execute`, and
`codemode.mutate`. This compact projection applies to both protocol generations;
otherwise the MCP 2026 stable-full rule would recreate the same initial catalog
overflow. Code Mode execution uses the caller's ordinary direct authority and
does not require durable result storage; durable continuation tools are simply
withheld when that storage is unavailable. Cursor users have reported both [the
absence of progressive tool loading](https://forum.cursor.com/t/cli-mcp-tool-limits/165642/8) and [failure to
apply `notifications/tools/list_changed`](https://forum.cursor.com/t/mcp-notifications-tools-list-changed-not-acted-on-mid-session/161459).
After changing this setting, reconnect a legacy client so its next initialize
handshake selects the new projection. A stateless MCP 2026 client selects the
projection independently on its next request.

## Staged rollout and rollback

The rollout uses the standard protocol generation, not a client-name claim, as
its primary boundary:

| Lane | Default | Compatibility action | Rollback |
|------|---------|----------------------|----------|
| MCP 2026-07-28 | Stable, paginated, authorization-filtered `tools/list` traversal | Leave the client name out of `GATEWAY_CODEMODE_ONLY_CLIENTS` unless the host cannot accept the full catalog | Remove the exact name; the next stateless request restores the stable full traversal |
| Legacy, compliant client | Progressive session disclosure plus `notifications/tools/list_changed` | Leave the client name out of `GATEWAY_EAGER_TOOLS_CLIENTS` | Add only the affected exact name to the allowlist |
| Legacy client without callable dynamic refresh | Per-client eager authorized catalog (`claude-code` and `codex-mcp-client` are the shipped default exceptions) | Add or remove exact names as compatibility is verified | Set `GATEWAY_EAGER_TOOLS_LIST=true` only as the fleet-wide emergency fallback; unset it to restore staged per-client behavior |
| Tool-capped client without dynamic refresh | Authorized gateway built-ins only; Code Mode discovers and invokes directly authorized operations | Add only the affected exact name to `GATEWAY_CODEMODE_ONLY_CLIENTS`; reconnect legacy clients | Remove the name and reconnect legacy clients; stateless clients apply either change on their next request; do not combine compact and eager postures |

`clientInfo.name` is self-asserted and selects only a context-size projection.
Every list re-runs profile, Cedar, schema-admission, and quarantine filters, and
every call re-runs governed dispatch. The metric
`mcp_tools_list_requests_total{protocol_generation,discovery_mode,client_class}`
exposes only the closed modes `progressive`, `eager_client`, `eager_global`,
`stable_full`, and `codemode_only`, with the closed client classes
`legacy_other`, `legacy_allowlisted`, `global_override`, `stateless`, and
`compact_allowlisted`. It never records a client name or payload. Use, for
example:

```promql
sum by (protocol_generation, discovery_mode, client_class) (
  rate(mcp_tools_list_requests_total[15m])
)
```

`mcp_tools_list_returned_tools` and `mcp_tools_list_serialized_bytes` are
per-response-page histograms with the same labels. The byte measurement is the
compact serialized `ListToolsResult` before the request-specific JSON-RPC
envelope and transport framing. The gateway counts those bytes with a sink
writer rather than allocating a second catalog-sized buffer.

The remaining rollout boundaries are contract-tested:

- catalog refresh wakes `subscriptions/listen` only after a real publication
  (`subscriptions_listen_wakes_only_on_catalog_changes`);
- the stable 2026 list is canonical and unchanged by compatibility search
  (`stateless_tools_list_is_stable_before_and_after_search`);
- eager listing re-checks an authorization change on the next request
  (`eager_projection_rechecks_authorization_on_every_list`);
- quarantine still refuses dispatch and hides type discovery
  (`quarantined_server_refuses_dispatch` and
  `search_tools_types_refuses_quarantined_tool_without_principal`); and
- the client-specific fallback affects only its matching legacy session while
  MCP 2026 ignores that allowlist
  (`eager_client_allowlist_applies_only_to_matching_session` and
  `stateless_tools_list_ignores_legacy_eager_client_allowlist`); and
- the compact allowlist removes upstream declarations, preserves Code Mode
  listing and dispatch, and supplies matching stateless discovery guidance
  (`codemode_only_client_allowlist_hides_upstream_declarations` and
  `stateless_codemode_only_client_gets_compact_catalog_and_guidance`).

Retire a legacy exception only after its `eager_client` series stays flat for
the chosen observation window. Retire the legacy projection itself only after
both `mcp_requests_total{protocol_generation="legacy"}` and every legacy mode
of `mcp_tools_list_requests_total` stay flat. A cached list is never evidence of
continued authorization: clients must tolerate a later list omission or call
refusal after policy, catalog, or quarantine changes.

## Wire ownership capture

Before changing descriptions or server instructions, capture all three
projections for the same authorization view:

1. the raw `server/discover` result and every page of raw `tools/list`;
2. the connector-adapted tool declarations; and
3. the host-registered declarations presented to the model runtime.

Keep captures outside git: an authorization-scoped catalog is operational
metadata even though it contains no credential values. Normalize each tool
surface to a standard `{ "tools": [...] }` document and run:

```sh
node scripts/report-tool-context.mjs raw-tools-list.json
node scripts/report-tool-context.mjs connector-tools.json
node scripts/report-tool-context.mjs host-tools.json
```

Compare `toolCount`, `toolsJsonBytes`, field groups, and
`repeatedDescriptionLeadingBlocks`. The raw contract is pinned by
`stateless_wire_keeps_server_instructions_out_of_tool_descriptions`: shared
guidance occurs exactly once in `server/discover` and zero times in raw tool
descriptions. Repetition introduced only in a later capture is owned by that
adapter or host. Kagi is a useful small canary, but the comparison is always
catalog-wide so a shared transformation cannot be mistaken for an
upstream-specific defect.

## Deployment measurement

Roll out in this order:

1. Capture the three surfaces and a baseline of request rate, returned-tool
   count, serialized bytes, and `tools/list` latency.
2. Verify capable hosts negotiate MCP 2026 and defer the standard catalog from
   model context. Keep direct qualified tool invocation as the portable path.
3. Unset `GATEWAY_EAGER_TOOLS_LIST`. Keep only exact, observed compatibility
   exceptions in `GATEWAY_EAGER_TOOLS_CLIENTS`. Put clients with both an
   initial tool cap and no dynamic refresh in `GATEWAY_CODEMODE_ONLY_CLIENTS`
   instead; the two client lists must not overlap.
4. Exercise a non-allowlisted legacy client through search, list-changed, list,
   and direct invocation. Exercise each allowlisted legacy client and one MCP
   2026 client through direct invocation. Reconnect each compact legacy client;
   issue a fresh request from each compact stateless client. Verify each list
   contains the Code Mode facade but no upstream declarations, then execute one
   discovered operation through Code Mode.
5. Confirm `eager_global` is flat, non-allowlisted legacy traffic is
   `progressive`, allowlisted traffic is `eager_client`, and MCP 2026 traffic is
   `stable_full`, and compact traffic is `codemode_only`. Compare p50/p95 bytes
   and latency to the baseline and verify task-level tool selection has not
   regressed.

If one client fails, select the exact asserted name in the posture that matches
its behavior while the client defect is investigated. Restore the process-wide
eager override only when multiple legacy client classes are simultaneously
unusable and no exact allowlist restores service; remove it again after
recovery.

## Private cache boundary

The stable projection remains `cacheScope: private` with `ttlMs: 0` until a
cache key and invalidation path bind all inputs that can change visibility:
tenant and principal authorization view, API-key/profile generation, Cedar
policy generation, catalog publication epoch, runtime/quarantine generation,
protocol projection, and page cursor. A catalog notification invalidates every
page immediately. No cache entry may cross authorization contexts, and a
positive TTL is not a substitute for reauthorization at invocation.

The Tantivy index lives in
[`index.rs`](../crates/waygate-mcp/src/index.rs) and is rebuilt after successful
upstream catalog publication. Live catalog changes use the independent
process-wide epoch so failed or descriptor-identical refreshes stay quiet.
