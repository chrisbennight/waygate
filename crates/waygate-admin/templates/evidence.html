Chain integrity planned

Tamper-evidence hash chain over the audit log (Monitor)

Required-write audit_log rows are linked per tenant by a hash chain sealed at insert time. Best-effort rows are append-only but unchained and are outside this verification report. Verify an arbitrary chain window with GET /api/v1/audit/verify?tenant_id=&from=&to= — it walks the chain and reports ok / mismatch / empty / incomplete. Because an empty result only means no chain-bearing rows matched the requested window, it does not establish full audit completeness; unchained rows may still exist. A full walk is an unbounded scan, so the page does not run it on load; the live "Verify now" button and per-marker breakdown are not yet implemented.
