Configured upstream MCP servers. Per-server manifests are edited on the Server Manifests page (or servers/*.yaml); use Reload manifests to apply the on-disk servers/*.yaml set's hot-reloadable changes (tool classifications, exchange, tier) in place. Connection-shape changes (url / command / auth / mtls / protocol / session isolation) are re-dialed live by Reload when the slot count is unchanged; a transport flip (stdio↔network) or a session.concurrency change resizes the slot pool and is rebuilt live by Reload — a restart is needed only if every new-shape dial fails. Operators can also recover a server in place — re-dial a down upstream or clear a drift quarantine — or refresh its catalog to replace a healthy session after the upstream adds tools. Expand a row (▸) to see its resolved connection, identity tier, and tool-risk summary; select a server name to browse its tools.
